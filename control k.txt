# Implement a Production-Grade Ctrl+K Command Palette for Pulse CRM

You are working on an existing production-style CRM application called **Pulse CRM**.

I need you to implement a **very robust, application-wide Ctrl+K / Command Palette system**.

This is an important core feature of the website. Do NOT implement a basic search modal. Build it as a **global command center** similar to the command palettes found in modern applications such as Linear, Notion, Slack, VS Code, GitHub, and HubSpot.

---

## 1. FIRST: UNDERSTAND THE EXISTING APPLICATION

Before writing code:

1. Inspect the complete frontend structure.
2. Identify:

   * routing/navigation system
   * layouts
   * sidebar
   * pages
   * authentication
   * permissions/roles
   * API client
   * existing search functionality
   * lead/contact/company/deal data structures
   * keyboard shortcut handling
   * modals/dialogs
   * state management
   * notification/toast system
3. Understand the existing UI design system.
4. Identify reusable components that should be used instead of creating duplicates.
5. Check whether a command palette/search component already exists.
6. Check whether Ctrl+K is already registered anywhere.
7. Check for keyboard-shortcut conflicts.
8. Check how navigation is implemented.

Do NOT immediately create files.

First understand the architecture and then implement Ctrl+K consistently with the existing application.

---

# 2. CORE REQUIREMENT

Ctrl+K must work **globally across the entire application**.

The user should be able to press:

**Ctrl + K**

from almost anywhere in the application and open the command palette.

Also support:

**⌘ + K** on macOS.

The command palette should:

* open instantly
* focus the search input automatically
* allow keyboard-only navigation
* support fuzzy search
* support commands
* support navigation
* support searching CRM records
* support actions
* support contextual actions
* show keyboard shortcuts
* remember/reuse recent commands where appropriate
* handle loading states
* handle errors gracefully
* work across route changes
* work without requiring the user to click anything

---

# 3. GLOBAL COMMAND PALETTE ARCHITECTURE

Create a reusable architecture similar to:

CommandPalette
↓
Command Registry
↓
Command Groups
↓
Command Search / Ranking
↓
Command Execution
↓
Navigation / Action / API / Modal

Do NOT hardcode everything directly inside the modal component.

Separate:

1. UI
2. command definitions
3. search/ranking
4. execution
5. keyboard handling
6. contextual commands
7. record search

The architecture should make it easy to add new commands later.

The search system should intelligently rank results.

For example, if the user types:

"acme"

1. exact name match
2. starts-with match
3. partial name match
4. email/domain match
5. company match
6. fuzzy match

Commands should also participate in search.

Example:

User types:

"lead"

Results could be:

### Actions

### Records

Acme Lead

### Navigation

icon,

}

# 14. PERMISSION AWARENESS

Commands must respect the application's authentication and authorization.

For example:

DO NOT show:

Create Lead

DO NOT show:

Do not merely hide the UI while allowing unauthorized execution.

Existing backend authorization remains the final authority.

---

# 15. LOADING STATES

The command palette must feel fast.

When searching backend records:

Show:

Searching...

Do not freeze the UI.

Use debouncing.

Cancel or ignore stale requests.

Example:

User types:

a
→ request

ac
→ previous request should not incorrectly overwrite the newer result

acm
→ newest request wins

# 16. ERROR HANDLING

Never allow Ctrl+K to crash the application.

"Unable to search records"

Provide a useful recovery option where appropriate.

Navigation errors should be handled safely.

API errors should not break the command palette.

* rich text editor

Do not register multiple global Ctrl+K listeners because of component re-renders.
